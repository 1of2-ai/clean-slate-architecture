# Architecture: Clean-Slate Architecture

## Commands (Replace per stack)

- Verify build & DAG boundaries: <check-dag>

## Authoring Rules
- Code isolation != feature isolation: Zero cross-slice imports controls code dependencies, never product collaboration. Default to top-down composition, typed ports, UI slot inversion, and open Capability registries in app/; use an EventLog only for genuine multi-surface fan-out (never polling loops, NotificationCenter domain buses, or static service locators). If peer slices sync duplicate models or trade back-and-forth callbacks through app/, merge them into one slice; never disguise a horizontal UI/engine layer or God-settings screen as a slice.
- Working set and Depth-2 cells: Scope tasks to spine/ + slices/<target>/ (SPEC.md, src/, tests/). Keep slices <= ~2.5k LOC flat in src/. Above ~2.5k LOC (or to isolate a heavy SDK), sub-seal once at Depth 2: kernel/ (shared pure types + state, zero I/O) <- cells/<cell>/ (direct kernel/ import, zero internal ports/DTOs/mini-EventLogs, zero peer-cell imports) <- thin src/ facade (sole target visible to app/). Touch app/ only for factory composition, routing, slots, or upstream policy/context gateways—never domain formatting, gating, or callback switchboards.
- Spine and opt-in libs: Keep spine/ports, spine/design (tokens, theme, and i18n only), and optional spine/runtime 100% domain-blind. Put shared UI kits, domain-free libraries, and host-only DTOs in opt-in libs/ packages forbidden to non-participating slices, and test fakes in dev-only test-support. If using spine/facts/, name facts in the producer's past-tense domain and compile only with >= 2 non-test modules. Duplicate small local helpers over growing spine/.
- Single state owner and runtime: Every piece of mutable truth has one owner—never maintain writable shadow copies across slices or processes. Use Profile 1 (optional KeyedStickyStore) for multi-surface reactive UI apps, and Profile 2 (synchronous ports + canonical host stream, or discrete facts + read-only disk projections) for embedded engines, harnesses, servers, and CLIs. Every slice is factory-scoped with dispose(), zero module-level singletons, and zero ambient OS globals.
- Kernels, specs, and loud errors: Separate behavioral invariants from tunable parameters in SPEC.md and prune superseded clauses. Model lifecycles and provenance with explicit sum types (zero boolean flag soup, string punctuation, or type escape hatches). Keep stateless work as plain functions; for stateful/async slices, put 100% of mutable state in a private(set) synchronous kernel (step for refusable commands, record for events) with zero discarded results (try? / _ =), zero shadow caches or re-entrancy booleans in runners/views, mid-stack UI callbacks only reporting into the kernel, and zero bare catch {} blocks.
- Verification and escalation: Test only outer slice boundaries in slices/<target>/tests/ (public package entrypoint + test-support fakes; zero per-cell harnesses, zero internal mocks, zero ../src or @testable imports) and cross-slice guarantees + multi-instance isolation in app/tests/. Write assertions and randomized invariants from SPEC.md + spine/ + entrypoint types and confirm they fail on a stub or bug before editing src/. If SPEC.md, spine/, and tests/ conflict, STOP and escalate; never weaken assertions.
- Subtraction-first refactoring (no compliance theater): Never wrap tangled code in pass-through callbacks or move domain glue into app/ just to pass check-dag, and never leave a legacy store alive beside a new slice behind a two-way sync bridge. Every refactor or port cutover must delete duplicate state owners, shadow flags, or legacy modules—or wipe src/* (and cells/*) to regenerate cleanly from locked SPEC.md + tests/.
