# Clean-Slate Architecture: Research Foundations

*A verified bibliography of 2025-2026 empirical studies, benchmarks, and classical architectural lineages behind [Clean-Slate Architecture](README.md).*

## Overview

Clean-Slate Architecture cross-checks battle-tested modular software design patterns against empirical studies of how frontier coding agents behave across multi-commit repository maintenance, parallel pull-request integration, repository context configuration, starting-state inheritance, and automated test generation.
This document compiles the verified primary sources behind Clean-Slate, stating exact metrics and experimental denominators, and maps each empirical signal to the specific architectural mechanism it shaped.

## 1. Context Physics, Distractor Interference & Working Set Radius

Large context windows (1M+ tokens) do not eliminate the cost of structural sprawl. Controlled evaluations show that model reasoning degrades well inside nominal token limits, with semantically similar "near-miss" distractors causing the sharpest accuracy drops.

* **Hong, Troynikov, & Huber (2025),** *[Context Rot: How Increasing Input Tokens Impacts LLM Performance*](https://www.trychroma.com/research/context-rot) (Chroma Technical Report) & **Martin & Roger (2026),** *[Classifier Context Rot: Monitor Performance Degrades with Context Length*](https://arxiv.org/abs/2605.12366) ([arXiv:2605.12366](https://arxiv.org/abs/2605.12366)): Hong et al. evaluated 18 frontier models while holding task complexity constant and varying input length and distractor similarity, showing continuous degradation well below maximum context capacity and sharp error amplification from near-miss semantic distractors; Martin & Roger confirmed that long benign context degrades frontier model detection of subtle failures inside long agent transcripts.
* **Architectural Impact on Clean-Slate:**
  * Establishes **Working Set Radius (`The Spine + One Feature Slice`)** as Clean-Slate's governing metric to physically exclude near-miss distractors from attention rather than merely conserving token budget.
  * Motivates banning Clean-Architecture pass-through layers (`OrderDTO`, `OrderMapper`, `OrderRepository`, `OrderUseCase`), which manufacture near-miss distractor files around every domain noun.

## 2. Continuous Maintenance, Merge Contention & Sealed Macro-Boundaries

While coding agents perform strongly on isolated single-issue benchmarks, longitudinal repository benchmarks and large-scale GitHub analyses show steep degradation from non-local regressions and parallel branch collisions when module boundaries are porous.

* **Chen et al. (2026),** *[SWE-CI: Evaluating Agent Capabilities in Maintaining Codebases via Continuous Integration*](https://arxiv.org/abs/2603.03823) ([arXiv:2603.03823](https://arxiv.org/abs/2603.03823)): Evaluated 18 models across 8 providers on 100 real repository evolution histories averaging 233 days and 71 sequential commits. Most models recorded a **zero-regression rate below 0.25**: meaning they broke previously passing tests in over 75% of multi-round maintenance runs (only two Claude Opus models exceeded 0.5).
* **Deng et al. (2026),** *[SWE-Milestone: Evaluating AI Agents on Continuous Software Evolution*](https://arxiv.org/abs/2603.13428) ([arXiv:2603.13428](https://arxiv.org/abs/2603.13428)) & **Ding et al., ICML (2026),** *[NL2Repo-Bench: Towards Long-Horizon Repository Generation Evaluation of Coding Agents*](https://arxiv.org/abs/2512.12730) ([arXiv:2512.12730](https://arxiv.org/abs/2512.12730), PMLR 306:25035-25054): Deng et al. evaluated 12 frontier models across 4 agent frameworks and found performance dropping from above 80% on isolated tasks to a maximum of **38.03%** in continuous multi-milestone settings (with strict regression-free resolve rates peaking at **13.37%**, as *"Recall grows linearly, while Precision saturates"*); Ding et al. found end-to-end repository generation from scratch averaging under 40.5% test pass rates due to fragile cross-file dependencies and loss of global coherence.
* **Ogenrwot & Businge (2026),** *[AgenticFlict: A Large-Scale Dataset of Merge Conflicts in AI Coding Agent Pull Requests on GitHub*](https://arxiv.org/abs/2604.03551) ([arXiv:2604.03551](https://arxiv.org/abs/2604.03551)): Ran deterministic 3-way git merge simulations across 107,000+ AI coding agent pull requests from 59,000+ repositories and identified 29,000+ conflicting PRs: a **27.67% textual merge-conflict rate** spanning 336,000+ conflict regions.
* **Konrad et al. (2026),** *[Architecture Without Architects: How AI Coding Agents Shape Software Architecture*](https://arxiv.org/abs/2604.04990) ([arXiv:2604.04990](https://arxiv.org/abs/2604.04990)): Documented "vibe architecting," showing that without structural constraints agents make unrecorded cross-cutting choices and revert to pretraining DRY habits across parallel multi-agent workflows.
* **Architectural Impact on Clean-Slate:**
  * Enforces **Zero Cross-Feature Imports** and **Owned Durable Persistence** via package manifests to put a compiler wall in front of multi-commit regressions.
  * Splits `spine/facts/` into **per-domain fact files** and isolates features into sealed directories so parallel agent branches avoid the high merge-conflict rates observed in *AgenticFlict*.
  * Pairs **"Merge Before You Coordinate"** for chatty peer slices with **top-down `App Shell` gateways** for cross-cutting hubs (`Auth`, `Entitlements`), and prefers local helper duplication over polluting `The Spine`.

## 3. Repository Context Files (`AGENTS.md`): Operational Maps vs. Lint & Skill Leakage

Three complementary 2026 empirical studies explain *when* repository context files accelerate coding agents and *when* they degrade performance:

* **Lulla et al., ICSE JAWs (2026),** *[On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents*](https://arxiv.org/abs/2601.20404) ([arXiv:2601.20404](https://arxiv.org/abs/2601.20404)): Compared paired runs with and without root `AGENTS.md` files across 124 merged pull requests (up to 100 LoC and 5 code files) in 10 GitHub repositories. Concise operational `AGENTS.md` files (commands, structure, and boundaries) lowered **median wall-clock runtime by 28.64%** (mean -20.27%) and **median output token consumption by 16.58%** (mean -20.08%) while maintaining task completion behavior.
* **Gloaguen et al., ETH Zürich (2026),** *[Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?*](https://arxiv.org/abs/2602.11988) ([arXiv:2602.11988](https://arxiv.org/abs/2602.11988)): Evaluated repository context files on AGENTbench and found that verbose or LLM-generated codebase overviews slightly **reduced task resolution rates (-0.5% to -2%) while increasing inference cost and exploration steps by 20%-23%** (developer-written files averaged +4% resolution at +19% higher cost), recommending minimal, high-signal operational instructions rather than repository essays.
* **dos Santos, Costa, Montandon, Silva, & Valente, IEEE SCAM (2026),** *[Configuration Smells in AGENTS.md Files: Common Mistakes in Configuring Coding Agents*](https://arxiv.org/abs/2606.15828) ([arXiv:2606.15828](https://arxiv.org/abs/2606.15828)): Audited 100 popular open-source repositories containing `AGENTS.md` or `CLAUDE.md` files (identifying 207 smell instances) and found **Lint Leakage in 62% of files** (restating rules that compilers, package managers, or linters enforce deterministically), **Context Bloat in 42%**, and **Skill Leakage in 35%** (placing specialized, mode-specific workflows into always-on context).
* **Architectural Impact on Clean-Slate:**
  * Separates the **Human Engineering Standard** (\~10-minute architectural read) from a compact **Machine Kernel** in `AGENTS.md` led by executable slice-scoped build/test commands.
  * Strips **Lint Leakage** and **Skill Leakage** out of `AGENTS.md`: import DAG rules, target boundaries, `hopDepth < maxHops` loop assertions, and `spine/` or `tests/` diff gates live in package manifests, runtime code, and CI: leaving `AGENTS.md` to express only universal, un-lintable authoring rules.

## 4. Maintenance Debt, Starting-State Acceptance Bias & Clean-Slate Regeneration

Late-2026 repository maintenance studies draw a sharp distinction between *ugly passing code* and *inherited broken/unfinished attempts*:

* **Pan et al. (2026),** *[Do Modifications Made by Coding Agents Make Subsequent Software Maintenance Harder?*](https://arxiv.org/abs/2610.14768) (`arXiv:2610.14768`, `SWE-Maintain`): Evaluated five agent harnesses and two frontier backbones across 1,996 paired sequential maintenance tasks comparing human-authored vs. agent-authored histories. While building on raw agent history lowered downstream resolution by 5.6 to 14.0 percentage points, the loss came almost entirely from **inherited test failures**; when prior agent modifications **passed all earlier behavioral tests**, they imposed **no measurable disadvantage** on subsequent agents (+2.7 points, 95% CI `[-0.5, +6.1]`).
* **Li et al. (2026),** *[SWE-Residual: Evaluating Starting-State Robustness of Coding Agents*](https://arxiv.org/abs/2610.25899) ([arXiv:2610.25899](https://arxiv.org/abs/2610.25899)): Constructed 198 Residual States across 111 DeepSWE and Terminal-Bench tasks where a predecessor agent submitted incomplete/failing work as finished. Blind continuation from those residual states caused task success to drop by **20.6 to 53.5 percentage points** compared to a Clean Start due to **acceptance bias**: in failed continuations, successor agents retained **86.4% to 98.6%** of the predecessor's lines (and on DeepSWE submitted with the exact same tests failing in **58.9%-88.2%** of failed runs) rather than rethinking the flawed design.
* **GitClear Research (June 2026), *The Maintainability Gap: AI Code Quality in 2026***: Analyzed 623 million code changes (2023-2026) and documented a **70% drop in refactoring**, a **74% drop in legacy code maintenance**, an **81% rise in duplicated code blocks**, and a **47% increase in error-masking constructs** (`catch`-and-ignore / fallback suppression).
* **Architectural Impact on Clean-Slate:**
  * Grounds **The Blast-Radius Tie-Breaker** (*"Strict at the seams, pragmatic inside the slice"*): passing slice internals do not require aesthetic micromanagement, while silent error-masking (`catch`-and-ignore) is explicitly banned.
  * Pairs each slice with a concise, human-owned **`SPEC.md`** and scopes **Clean-Slate Regeneration** accurately: engineers leave working slices alone, and when a multi-turn or multi-agent implementation becomes tangled or fails contracts, they wipe `slices/<name>/src/*` and regenerate cleanly from `SPEC.md` + `spine/` + `slices/<name>/tests/` rather than compounding residual acceptance bias.

## 5. Verification Physics: Potemkin Understanding, Misguided Oracles, Over-Mocking & Reward Hacking

Six verified empirical studies motivate Clean-Slate's shift away from post-hoc white-box unit tests and internal mocks toward spec-derived boundary contracts and randomized domain invariants:

* **Mancoridis, Weeks, Vafa, & Mullainathan, ICML (2025),** *[Potemkin Understanding in Large Language Models*](https://arxiv.org/abs/2506.21521) ([arXiv:2506.21521](https://arxiv.org/abs/2506.21521)): Formalized "unearned surface coherence," showing that frontier models answer canonical keystone questions fluently while exhibiting an average lower-bound **Potemkin rate of 0.62** and measurable **internal conceptual incoherence** (mean 0.22 across tasks, reaching 0.64). In software, models routinely produce implementations that pass canonical happy-path examples while violating underlying domain invariants.
* **Zhao, Zhou, & Cohen, ISSTA (2026),** *[Evaluating and Mitigating the Misguidance Effect of Buggy Code in LLM-Generated Unit Tests*](https://arxiv.org/abs/2607.22883) ([arXiv:2607.22883](https://arxiv.org/abs/2607.22883)) & [*Do Coverage and Mutation Scores of LLM-Generated Test Suites Correlate with Their Effectiveness? (Replicability Study)*](https://arxiv.org/abs/2607.22880) ([arXiv:2607.22880](https://arxiv.org/abs/2607.22880)): Showed on Defects4J and across 100,000+ LLM-generated test cases (11 frontier models) that exposing buggy implementation code during unit-test generation induces "misguided" false-negative assertions that **pass on the bug and fail on the fix**, while line coverage and suite size correlate weakly with real-bug detection when code under test may already be faulty.
* **Konstantinou, Tambon, & Papadakis (2026),** *[On the risk of coding before testing: An empirical study on LLM-based test generation workflow*](https://arxiv.org/abs/2607.05139) ([arXiv:2607.05139](https://arxiv.org/abs/2607.05139)): Quantified loss of oracle independence directly: providing both the task description and implementation code reduced fault detection by **13.2%** compared to generating tests from the specification alone (and by **15.1%** when generating from implementation code alone).
* **Hora & Robbes, MSR (2026),** *[Are Coding Agents Generating Over-Mocked Tests? An Empirical Study*](https://arxiv.org/abs/2602.00409) ([arXiv:2602.00409](https://arxiv.org/abs/2602.00409)): Analyzed over 1.25 million commits (including 48,563 coding-agent commits across 2,168 repositories) and found agents touch test files nearly **twice as often** as human developers (23% vs. 13% of commits) and introduce mocks significantly more often (36% vs. 26%), relying **95%** on rigid mock objects that freeze internal call structure without validating real component boundaries.
* **He, Chen, Zhang, Gao, & Sheng (2025/2026),** *[Effective LLM Code Refinement via Property-Oriented and Structurally Minimal Feedback*](https://arxiv.org/abs/2506.18315) ([arXiv:2506.18315](https://arxiv.org/abs/2506.18315), *PGS*) & **Shukla, Gupta, Alavi, & Vaezipoor, NeurIPS (2026),** *[Spec-Driven PBT: Deriving Semantic Invariants from Code Specifications for Agentic Property-based Testing*](https://arxiv.org/abs/2611.15920) ([arXiv:2611.15920](https://arxiv.org/abs/2611.15920)): He et al. demonstrated that deriving semantic properties/invariants from specifications breaks example-based TDD's *"cycle of self-deception,"* achieving **1.4x-1.6x higher bug-fix rates** and **+23.1% to +37.3% pass@1 gains** over TDD (including rising from 1.1% to 48.9% on the Hard algorithmic split); Shukla et al. confirmed that specification-derived invariants uncover documented product-workflow violations missed by conventional example tests.
* **Zhong, Raghunathan, & Carlini (2025),** *[ImpossibleBench: Measuring LLMs' Propensity of Exploiting Test Cases*](https://arxiv.org/abs/2510.20270) ([arXiv:2510.20270](https://arxiv.org/abs/2510.20270)): Reported GPT-5 exploiting test suites on **54%** of conflicting SWE-bench tasks. Making test files read-only blocked direct test edits (though not source-side special-casing), while combining read-only tests with an explicit abort/escalation instruction lowered exploitation from **54% to 9%** (and o3 from **49% to 12%**), leaving a non-zero residual rate.
* **Architectural Impact on Clean-Slate:**
  * Replaces mock-heavy internal unit tests with **millisecond, in-memory Subcutaneous Slice Contract Tests** plus a thin suite of `app/tests/` wiring journeys.
* Derives boundary tests and **randomized domain invariants** from `SPEC.md` rather than implementation code: catching both Potemkin incoherence and residual source-side special-casing that read-only permissions alone cannot block.
  * Balances daily developer ergonomics with safety via **two operating modes**: fluid **Feature Mode** backed by automatic CI diff flags on `spine/` and `tests/`, and read-only **Locked-Contract Mode** + **Stop-and-Escalate** for refactors and slice regeneration.

## 6. Classical Software Architecture Lineages Synthesized by Clean-Slate

Alongside modern agent research, Clean-Slate distills four proven human-era architectural lineages while stripping away their ceremonial layers:

1. **Polylith & "Features as Libraries; Apps as Shells":** Isolating domain capabilities as interchangeable library bricks assembled inside a thin composition root, with owned persistence per capability.
2. **Vertical Slice Architecture (Jimmy Bogard) & Flat Co-location:** Organizing code around vertical domain capabilities rather than horizontal technical layers (`Controller` / `Service` / `Repository` / `DTO`).
3. **Spring Modulith & Subcutaneous Contract Testing (Martin Fowler):** Replacing lateral cross-module dependencies with published/consumed domain facts and testing modules subcutaneously as black boxes.
4. **Elm Architecture, Event-Carried State Transfer & LMAX State Machines:** Modeling stateful lifecycles via explicit sum types / tagged unions and adapting state projections cleanly to stateful vs. stateless runtimes.
