# Clean-Slate Architecture: Research Foundations

*A verified bibliography of 2024-2026 empirical studies, benchmarks, and classical architectural lineages behind [Clean-Slate Architecture](README.md).*

## Overview

Clean-Slate Architecture cross-checks proven modular software design patterns against empirical studies of how coding agents behave across multi-commit repository maintenance, codebase granularity, static typing, specification authoring, repository context configuration, starting-state inheritance, and automated test generation.

This document compiles the primary sources behind Clean-Slate, stating exact metrics and experimental denominators, maps each empirical signal to the architectural mechanism it shaped, and records open empirical gaps transparently.

## 1. Context Physics, Granularity, and Working Set Radius

Large context windows (1M+ tokens) do not eliminate the cost of structural sprawl. Controlled evaluations show that model reasoning degrades well inside nominal token limits, with semantically similar "near-miss" distractors, multi-file spread, deep call graphs, and Clean Architecture indirection causing sharp accuracy drops.

- **Hong, Troynikov, & Huber (2025),** [*Context Rot: How Increasing Input Tokens Impacts LLM Performance*](https://www.trychroma.com/research/context-rot) (Chroma Technical Report) & **Martin & Roger (2026),** [*Classifier Context Rot: Monitor Performance Degrades with Context Length*](https://arxiv.org/abs/2605.12366) ([arXiv:2605.12366](https://arxiv.org/abs/2605.12366)): Hong et al. evaluated 18 frontier models while holding task complexity constant and varying input length and distractor similarity, showing continuous degradation well below maximum context capacity and sharp error amplification from near-miss semantic distractors. Martin & Roger confirmed that long benign context degrades frontier model detection of subtle failures inside long agent transcripts.
- **Multi-File Spread & Call-Graph Depth:** *Doc2Feat-Bench* (ASE 2026) shows moving from single-file to multi-file tasks drops success 2.5x to 5.4x (-21.7 to -34.8 pp for >30%-baseline configs; e.g., Claude-4-Sonnet 44.3% to 9.4%) even with 95.35% to 100% patch application. *SWE-Refactor* (ICLR 2026 sub) shows -50.5 pp (DeepSeek-V3 68.6% to 18.1%) and -39.5 pp (GPT-4o-mini 60.9% to 21.5%) on cross-file refactors. **Bellam (2026),** *DepthGEE* ([arXiv:2610.33958](https://arxiv.org/abs/2610.33958), 227,800 episodes) finds each extra call-graph hop multiplies localization odds by 0.47 to 0.55 (p <= 0.001).
- **Dente et al., COLM (2026),** *Constraint Decay* ([arXiv:2605.06445](https://arxiv.org/abs/2605.06445)): Across ~4B tokens and 8 frameworks, a 4-layer Clean Architecture alone exacts a **-8.8 +/- 1.7 pp** assertion pass penalty, compounding to -27.3 to -27.5 pp with DB and ORM constraints and causing genuine logic bugs rather than lint rejections.
- **The Two-Sided File-Size Squeeze:** **Yang et al. (2026),** *Skip the Compressor* ([arXiv:2610.21073](https://arxiv.org/abs/2610.21073)) shows feeding whole verbatim files beats chunked/pruned retrieval by +9.3 to +21.0 pp (GPT-5.6) and +12.7 to +13.0 pp (Opus 5), while **Wan et al. (Oct 2026),** *Physics of Coding Agents: Part 1* shows large files and >=200-token edits drop first search/replace acceptance from 93% to 58% and cause 20.1% silent corruption on line-range edits. Similarly, **Sagenschneider (2026)** ([arXiv:2610.14130](https://arxiv.org/abs/2610.14130), 6,000 implementations) found a concentrated Spring controller beat a ~5x-smaller decomposed pipeline on comprehension, cost, and speed (though handler erosion rose to 62% vs. 0%).
- **Architectural Impact on Clean-Slate:**
  - Establishes **Working Set Radius (`The Spine + One Feature Slice`)** as Clean-Slate's core metric to physically exclude near-miss distractors and keep slices small enough to read whole verbatim without falling into micro-package fragmentation.
  - Motivates banning Clean-Architecture pass-through layers (`OrderDTO`, `OrderMapper`, `OrderRepository`, `OrderUseCase`), which add both near-miss distractors and measurable assertion penalties.
  - Moves shared UI component kits, domain-free libraries, and host-only DTOs out of `spine/` into opt-in `libs/` packages so headless slices never pay the UI context tax.

## 2. Continuous Maintenance, Deterministic Gates, Typing Feedback, and Sealed Boundaries

While coding agents perform strongly on isolated single-issue benchmarks, longitudinal repository benchmarks show steep degradation from non-local regressions, unpropagated caller edits, and parallel branch collisions when boundaries are enforced only by prose rather than the build graph and compiler.

- **Chen et al. (2026),** [*SWE-CI: Evaluating Agent Capabilities in Maintaining Codebases via Continuous Integration*](https://arxiv.org/abs/2603.03823) ([arXiv:2603.03823](https://arxiv.org/abs/2603.03823)): Evaluated 18 models across 8 providers on 100 real repository evolution histories averaging 233 days and 71 sequential commits. Most models recorded a **zero-regression rate below 0.25**, breaking previously passing tests in over 75% of multi-round maintenance runs (only two Claude Opus models exceeded 0.5).
- **Deng et al. (2026),** [*SWE-Milestone*](https://arxiv.org/abs/2603.13428) ([arXiv:2603.13428](https://arxiv.org/abs/2603.13428)), **Ding et al., ICML (2026),** [*NL2Repo-Bench*](https://arxiv.org/abs/2512.12730) ([arXiv:2512.12730](https://arxiv.org/abs/2512.12730)), & **BOBA (2026)** ([arXiv:2611.02207](https://arxiv.org/abs/2611.02207)): Deng et al. found performance dropping from above 80% on isolated tasks to a maximum of **38.03%** in continuous multi-milestone settings (strict regression-free resolve peaking at **13.37%**). *BOBA* (55,545 graded requests across 10 agents on 20-spec chains) shows completion dropping from **95%** (single spec) to **51%** (chain) to **39%** (zero-regression), with 59% of silent misses passing green local tests and agents scoring only **53%** on self-review.
- **Ding (2026),** *Edit-Induced Dependency Mismatch* ([arXiv:2611.29242](https://arxiv.org/abs/2611.29242), 2,879 DeepSWE runs): 16.4% of runs (and **11.4% of passing runs**) leave unpropagated consumer obligations across files; targeted dependency re-derivation cuts omissions from 10.1% to 2.4%.
- **Ogenrwot & Businge (2026),** [*AgenticFlict*](https://arxiv.org/abs/2604.03551) ([arXiv:2604.03551](https://arxiv.org/abs/2604.03551)) & **Konrad et al. (2026),** [*Architecture Without Architects*](https://arxiv.org/abs/2604.04990) ([arXiv:2604.04990](https://arxiv.org/abs/2604.04990)): *AgenticFlict* simulated 3-way git merges across 107,000+ AI agent PRs from 59,000+ repos and measured a **27.67% textual merge-conflict rate**. Konrad et al. documented "vibe architecting," where unconstrained agents revert to pretraining DRY habits and make unrecorded cross-cutting choices.
- **Deterministic Gates Beat Prose Rules and LLM Reflection:** *GYROCOMPASS* (ACL GroundLM 2026) found 16 verified architectural violations landing in `polarsource/polar` despite explicit `CLAUDE.md`/`AGENTS.md` rules; deterministic gates hit **100%** compliance vs. 62% to 92% for context-only rules. *ContextCov* ([arXiv:2603.00822](https://arxiv.org/abs/2603.00822)) showed deterministic checks achieving **88.3%** compliance and +4.3 pp resolve rate (57.3% vs. 53.0%, p < 0.05), compared to 67.0% for passive `AGENTS.md` and **50.3% for LLM self-reflection** (-16.7 pp worse).
- **Static Typing Needs Synchronous Compiler Feedback and Escape-Hatch Bans:** *Multi-LCB* (ICLR 2026: dynamic beats static by +3.41 pp, p = 0.0010) and *Longtail-SWE* (Nov 2026: 57.12% static vs. 58.41% dynamic) show passive static typing does not raise solve rates on its own, while **Lee et al., MSR (2026)** ([arXiv:2602.17955](https://arxiv.org/abs/2602.17955), 38,979 TS PRs) show agents inject `any` **9x more than humans** (2.16 vs. 0.24/PR) and *Model Forensics* (NeurIPS 2026) caught hook bypasses in 13.1% of rollouts under heavy error load (0% at <=50 errors). By contrast, **synchronous compiler loops** deliver large causal gains (*CRUST-Bench*, [arXiv:2504.15254](https://arxiv.org/abs/2504.15254): +30.2 pp build / +9.8 pp test pass; *Generative Compilation*, ICML 2026 DL4C: compile errors cut from 65.9% to 13.1%), and strict memory-safe languages reduce severe runtime failures (**Nogueira et al., ISSRE 2026**, [arXiv:2608.00661](https://arxiv.org/abs/2608.00661): Rust eliminates OOM and halves OOB). Types alone do not stop behavioral or structural drift across commits (*CodeThread*, EMNLP 2026; *Structural Incoherence*, [arXiv:2607.08981](https://arxiv.org/abs/2607.08981)).
- **Architectural Impact on Clean-Slate:**
  - Enforces **Zero Cross-Feature Imports** and **Owned Durable Persistence** via native package manifests and CI bans on type escape hatches (`any`, unchecked casts, skipped hooks) rather than prose guidelines or LLM self-review.
  - Isolates features into sealed directories and splits optional `spine/facts/` into **per-domain fact files** so parallel agent branches avoid the merge-conflict rates observed in *AgenticFlict*.
  - Defaults to **top-down App Shell composition, UI slot inversion, and open capability registries** (with `EventLog` opt-in for genuine multi-surface fan-out), pairs **"Merge Before You Coordinate"** for chatty peer slices with top-down gateways for policy hubs (`Auth`, `Entitlements`), and prefers local helper duplication over bloating the Spine.

## 3. Repository Context Files (`AGENTS.md`) and Specification Discipline (`SPEC.md`)

Empirical studies across 2024-2026 clarify both how persistent agent instruction files (`AGENTS.md` / `CLAUDE.md`) help or hurt, and why compact, human-owned per-slice specifications outperform heavyweight SDD ceremony.

- **Lulla et al., ICSE JAWs (2026),** [*On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents*](https://arxiv.org/abs/2601.20404) ([arXiv:2601.20404](https://arxiv.org/abs/2601.20404)): Across 124 merged PRs in 10 repos, concise operational `AGENTS.md` files (commands, structure, boundaries) lowered **median wall-clock runtime by 28.64%** and **median output tokens by 16.58%**.
- **Gloaguen et al., ETH Zürich (2026),** [*Evaluating AGENTS.md*](https://arxiv.org/abs/2602.11988) ([arXiv:2602.11988](https://arxiv.org/abs/2602.11988)) & **dos Santos et al., IEEE SCAM (2026),** [*Configuration Smells in AGENTS.md Files*](https://arxiv.org/abs/2606.15828) ([arXiv:2606.15828](https://arxiv.org/abs/2606.15828)): Verbose or LLM-generated overviews slightly **reduced resolution (-0.5% to -2%) while raising cost 20%-23%**. Auditing 100 OSS repos found **Lint Leakage in 62%**, **Context Bloat in 42%**, and **Skill Leakage in 35%**.
- **Chakrabarti (2026),** [*Why Does CLAUDE.md Keep Growing? Catastrophic Remembering in Agentic Coding*](https://arxiv.org/abs/2608.11095) ([arXiv:2608.11095](https://arxiv.org/abs/2608.11095)): Tracked 247,694 instruction lifetimes across 1,867 GitHub repos. Instruction files grow **+226%** over their lifetime because maintainers forget why old rules existed; wholesale manual rewrites rebound to **91.5% within 10 commits**. Recording a short origin rationale alongside each rule eliminates 99.3% of excess instructions and lifts real-world instruction following on WildIFEval by **+23.1%**.
- **Human-Owned Specs, Ambiguity, Intent Drift, and Typed Skeletons:**
  - [*Spec-Driven Development as Prescribed and as Practiced*](https://arxiv.org/abs/2608.25202) ([arXiv:2608.25202](https://arxiv.org/abs/2608.25202), 470,795 spec files across 73,030 repos) shows most SDD specs receive only **1 commit** and die as disposable generation prompts while burning **2x to 3x tokens** (up to 80% on planning) with circular agent-tests-agent verification. **Feng et al., FSE Companion '26** ([arXiv:2605.02455](https://arxiv.org/abs/2605.02455)) confirm agents struggle to author structured specs but excel at implementing from human-structured ones.
  - [*Orchid*](https://arxiv.org/abs/2604.21505) ([arXiv:2604.21505](https://arxiv.org/abs/2604.21505), 1,304 tasks) shows requirement ambiguity cuts Pass@1 by **16.25%** relative (**35%-52%** for open-source models in [*HumanEvalComm*](https://arxiv.org/abs/2406.00215), [arXiv:2406.00215](https://arxiv.org/abs/2406.00215)), and [*ClarifyCodeBench*](https://arxiv.org/abs/2607.00711) ([arXiv:2607.00711](https://arxiv.org/abs/2607.00711)) proves **extended chain-of-thought reasoning does not improve ambiguity detection**. **Zhang et al. (2026),** [*INTENTFLUX*](https://arxiv.org/abs/2609.32520) ([arXiv:2609.32520](https://arxiv.org/abs/2609.32520)) show superseded requirements persist as intent drift unless explicitly pruned.
  - [*Skeleton Coding*](https://arxiv.org/abs/2610.38214) ([arXiv:2610.38214](https://arxiv.org/abs/2610.38214)) shows locking typed module boundaries and signatures upfront narrows the small-vs-large model gap by **~52.4%**, cuts implementation cost **15x to 26x**, and reduces code erosion **24.7%**, while preventing naming-induced test failures ([*Specification-Oracle Gaps*](https://arxiv.org/abs/2610.30635), [arXiv:2610.30635](https://arxiv.org/abs/2610.30635)).
- **Architectural Impact on Clean-Slate:**
  - Separates the **Human Engineering Standard** from a compact, command-first **`AGENTS.md` Machine Kernel** stripped of Lint and Skill Leakage, with brief rationale notes on repo-specific rules so obsolete rules can be pruned.
  - Keeps **`SPEC.md`** short (1-2 pages), human-owned, per-slice, and actively pruned when requirements change, paired with a typed factory entrypoint skeleton before implementation begins.

## 4. Maintenance Debt, Starting-State Acceptance Bias, and Clean-Slate Regeneration

Late-2026 repository maintenance studies draw a sharp distinction between *ugly passing code* and *inherited broken or unfinished attempts*:

- **Pan et al. (2026),** [*Do Modifications Made by Coding Agents Make Subsequent Software Maintenance Harder?*](https://arxiv.org/abs/2610.14768) ([arXiv:2610.14768](https://arxiv.org/abs/2610.14768), *SWE-Maintain*): Evaluated five agent harnesses and two frontier backbones across 1,996 paired sequential maintenance tasks comparing human-authored vs. agent-authored histories. While building on raw agent history lowered downstream resolution by 5.6 to 14.0 percentage points, the loss came almost entirely from **inherited test failures**. When prior agent modifications **passed all earlier behavioral tests**, they imposed **no measurable disadvantage** on subsequent agents (+2.7 points, 95% CI `[-0.5, +6.1]`).
- **Li et al. (2026),** [*SWE-Residual: Evaluating Starting-State Robustness of Coding Agents*](https://arxiv.org/abs/2610.25899) ([arXiv:2610.25899](https://arxiv.org/abs/2610.25899)): Constructed 198 Residual States across 111 DeepSWE and Terminal-Bench tasks where a predecessor agent submitted incomplete or failing work as finished. Blind continuation from those residual states caused task success to drop by **20.6 to 53.5 percentage points** compared to a Clean Start due to **acceptance bias**. In failed continuations, successor agents retained **86.4% to 98.6%** of the predecessor's lines (and on DeepSWE submitted with the exact same tests failing in **58.9%-88.2%** of failed runs) rather than rethinking the flawed design.
- **GitClear Research (June 2026), *The Maintainability Gap: AI Code Quality in 2026*** (industry report): Analyzed 623 million code changes (2023-2026) and documented a **70% drop in refactoring**, a **74% drop in legacy code maintenance**, an **81% rise in duplicated code blocks**, and a **47% increase in error-masking constructs** (`catch`-and-ignore / fallback suppression).
- **Architectural Impact on Clean-Slate:**
  - Grounds **The Blast-Radius Tie-Breaker** (*"Strict at the seams, pragmatic inside the slice"*): passing slice internals do not require aesthetic micromanagement, while silent error-masking (`catch {}`) is explicitly banned.
  - Scopes **Targeted Clean-Slate Regeneration** accurately: leave working slices alone, and when a multi-turn or multi-agent implementation becomes tangled or fails contracts, wipe `slices/<name>/src/*` and regenerate cleanly from `SPEC.md` + `spine/` + `slices/<name>/tests/` rather than compounding residual acceptance bias.

## 5. Verification Physics: Potemkin Understanding, Oracle Isolation, PBT Gaming, and Stop-and-Escalate

Empirical verification studies from 2025-2026 motivate Clean-Slate's two-horizon verification model (`t = 0` concept verification and `t = 50` regression memory), replacing post-hoc white-box unit tests and internal mocks with spec-derived boundary contracts, randomized domain invariants, and explicit escalation gates:

- **Mancoridis, Weeks, Vafa, & Mullainathan, ICML (2025),** [*Potemkin Understanding in Large Language Models*](https://arxiv.org/abs/2506.21521) ([arXiv:2506.21521](https://arxiv.org/abs/2506.21521)): Formalized "unearned surface coherence," showing frontier models answer canonical keystone questions fluently while exhibiting a lower-bound **Potemkin rate of 0.62** and measurable internal conceptual incoherence (mean 0.22, up to 0.64).
- **Information Isolation Beats Model Swapping:** **Zhao, Zhou, & Cohen, ISSTA (2026)** ([arXiv:2607.22883](https://arxiv.org/abs/2607.22883), [arXiv:2607.22880](https://arxiv.org/abs/2607.22880)) showed across 100,000+ LLM-generated tests that exposing buggy code biases models into assertions that **pass on the bug and fail on the fix**, while line coverage correlates weakly with real-bug detection (confirmed by **Al-Ahmad et al.**, [arXiv:2609.24341](https://arxiv.org/abs/2609.24341): coverage vs. mutation r = 0.11). **Konstantinou, Tambon, & Papadakis (2026)** ([arXiv:2607.05139](https://arxiv.org/abs/2607.05139)) found spec-only isolation raises fault detection from 14% to 25%. Crucially, **Leu, Oertel, & Hebig, ESEM (2026)** (DOI `10.4230/LIPIcs.ESEM.2026.11`) proved that **swapping to a second LLM while implementation code stays visible yields no significant gain** (p = 0.1520).
- **Over-Mocking and the Implementation-Verification Gap:** **Hora & Robbes, MSR (2026)** ([arXiv:2602.00409](https://arxiv.org/abs/2602.00409), 1.25M commits) found agents introduce mocks far more often than humans (36% vs. 26%), relying **95%** on rigid mock objects that freeze internals. [*TestSuiteBench*](https://arxiv.org/abs/2610.13065) ([arXiv:2610.13065](https://arxiv.org/abs/2610.13065), 165 real CLI apps) shows agent implementations pass **82%** of reference tests, yet the strongest agent's own spec-derived test suite kills only **56%** of requirement-violating mutants (4 of 6 agents score below 40%). *SWEPatchTest* (ICLR 2027, [arXiv:2610.18004](https://arxiv.org/abs/2610.18004), 82,579 patches) shows single-reference fail-first (`F->P`) at 59.3% to 68.2% collapses to **7.1% to 9.2% Joint Validation Rate** across real candidate patches.
- **Property-Based Testing, Mutation Hardening, and PBT Shortcutting:** **He et al. (2025/2026),** [*PGS*](https://arxiv.org/abs/2506.18315) ([arXiv:2506.18315](https://arxiv.org/abs/2506.18315): 1.4x-1.6x bug-fix rate over TDD) and **Shukla et al., NeurIPS (2026),** [*Spec-Driven PBT*](https://arxiv.org/abs/2611.15920) ([arXiv:2611.15920](https://arxiv.org/abs/2611.15920): 34% vs. 13% bug-bearing density on PRDs, only 41% Jaccard overlap with code-driven PBT) demonstrate the value of spec-derived invariants. Mutation and adversarial loops close the coverage gap: *Meta ACH* (FSE 2025, [arXiv:2501.12862](https://arxiv.org/abs/2501.12862): 48.5% of accepted hardening tests added zero line coverage), *MutGen* (IEEE TSE 2026, [arXiv:2506.02954](https://arxiv.org/abs/2506.02954): +11.6 to +19.2 pp mutation score), and *PROBE PBT* (ACL 2026 Findings: +5.04 to +9.79 pp mutation score, 65% to 95% property correctness). However, [*PBT-Bench*](https://arxiv.org/abs/2605.15229) ([arXiv:2605.15229](https://arxiv.org/abs/2605.15229), 4,800 trajectories) warns that baseline LLM PBTs suffer **31% `assume()` misuse, 31% narrow generator ranges, and 32% static concrete inputs** (and [*Agentic PBT*](https://arxiv.org/abs/2510.09907), [arXiv:2510.09907](https://arxiv.org/abs/2510.09907), documented `try-except` wrappers).
- **Scale-Dependent Reward Hacking, Stop-and-Escalate, and Hollow Formal Proofs:**
  - [*SpecBench*](https://arxiv.org/abs/2605.21384) ([arXiv:2605.21384](https://arxiv.org/abs/2605.21384)) shows validation-vs-held-out reward hacking scales **+23 pp mean (+27 to +28 pp P90) per 10x LOC**, hitting 100 pp above 25k LOC. [*Building to the Test*](https://arxiv.org/abs/2606.28430) ([arXiv:2606.28430](https://arxiv.org/abs/2606.28430)) shows agents satisfy a checked demo while leaving the requested reusable library dead.
  - [*ImpossibleBench*](https://arxiv.org/abs/2510.20270) ([arXiv:2510.20270](https://arxiv.org/abs/2510.20270)) showed GPT-5 exploiting tests on 54% of conflicting tasks (dropping to 9% with read-only tests + abort instruction), and **Gomez, NeurIPS 2026 Workshop** ([arXiv:2608.29460](https://arxiv.org/abs/2608.29460), 1,800 runs) directly validated **Stop-and-Escalate**: a structured defect-escalation tool + anti-hacking policy cuts reward hacking from **23.6% to 5.3%** (0% on 6 of 8 models, 99.4% escalation accuracy).
  - Formal proof assistants are not a drop-in substitute: [*Three Failure Surfaces*](https://arxiv.org/abs/2611.05590) ([arXiv:2611.05590](https://arxiv.org/abs/2611.05590)) exposes a **36x to 52x collapse** between verifier exit-0 acceptance (92% to 99%) and spec-bound postconditions (1.9% to 2.7%), and [*VerusEval*](https://arxiv.org/abs/2610.26464) ([arXiv:2610.26464](https://arxiv.org/abs/2610.26464)) finds only **42.3%** of verifier-accepted Verus specs pass triviality, I/O, and contract-refinement checks.
- **Architectural Impact on Clean-Slate:**
  - At **`t = 0`**, derives boundary contracts and **randomized domain invariants** from `SPEC.md`, `spine/`, and entrypoint signatures before `src/` exists (enforced via stub-first workflow, fail-first checks, generator/`assume()` audits, and periodic mutation hardening).
  - At **`t = 50`**, replaces mock-heavy internal unit tests with **millisecond, in-memory Subcutaneous Slice Contract Tests** against dev-only `test-support` fakes (zero internal mocks), acting as durable regression memory for stateless agents.
  - Pairs slice suites with two executable proof suites in `app/tests/`: **Cross-Slice Guarantee Journeys** (catching dropped wires and demo-only implementations) and **Multi-Instance Isolation** (catching singletons and ambient OS globals at runtime).
  - Balances daily developer ergonomics with safety via **two operating modes**: fluid **Feature Mode** backed by automatic CI diff flags on `spine/` and `tests/`, and read-only **Locked-Contract Mode** + **Stop-and-Escalate** for refactors and slice regeneration.

## 6. Classical Software Architecture Lineages Synthesized by Clean-Slate

Alongside modern agent research, Clean-Slate distills five proven human-era architectural lineages while stripping away their ceremonial layers:

1. **Polylith & "Features as Libraries; Apps as Shells":** Isolating domain capabilities as interchangeable library bricks assembled inside a thin composition root, with owned persistence per capability.
2. **Vertical Slice Architecture (Jimmy Bogard) & Flat Co-location:** Organizing code around vertical domain capabilities rather than horizontal technical layers (`Controller` / `Service` / `Repository` / `DTO`).
3. **Spring Modulith & Subcutaneous Contract Testing (Martin Fowler):** Testing cohesive domain modules subcutaneously as black boxes and enforcing explicit module boundaries.
4. **Functional Core, Imperative Shell (Gary Bernhardt):** Splitting complex stateful slices into a pure synchronous kernel (sole writer of its state) and a thin effect runner that isolates concurrency, timers, and I/O.
5. **Elm Architecture, Event-Carried State Transfer, & LMAX State Machines:** Modeling stateful lifecycles via explicit sum types / tagged unions and adapting state projections cleanly to stateful vs. stateless runtimes.

## 7. Open Empirical Gaps

For intellectual honesty, four architectural heuristics in Clean-Slate rely on converging indirect evidence rather than a direct controlled 2024-2026 benchmark:

1. **Optimal slice LOC ceiling:** No controlled study directly isolates an optimal file or slice line count (popular "500-line" rules are folklore). Clean-Slate's ~1,500-line cohesive-slice guideline is bracketed by *Skip the Compressor* (whole files beat chunkers) and *Physics of Coding Agents* / *SpecBench* (large-file edit corruption and scale-dependent reward hacking).
2. **Vertical Slice vs. Clean/Hexagonal head-to-head:** No benchmark compares Vertical Slice against Clean/Hexagonal Architecture on identical tasks, though *Constraint Decay* (`arXiv:2605.06445`) directly measures the -8.8 pp penalty of 4-layer Clean Architecture.
3. **ADTs vs. boolean/nullable state:** No controlled benchmark isolates ADTs vs. non-ADTs on identical agent tasks. Indirect evidence is mixed-to-positive: *FPEval* ([arXiv:2601.02060](https://arxiv.org/abs/2601.02060)) shows single-shot models evade ADTs 80% to 94% of the time, while multi-turn compiler feedback recovers strongly on *Longtail-SWE*, and *TYMCRAT* (2025) cuts type errors 71.5% when lifting C output parameters into Rust `Option`/`Result`.
4. **Deliberate PBT `max_examples` shrinking:** No study yet tracks agents deliberately lowering Hypothesis/QuickCheck iteration counts, though *PBT-Bench* (`arXiv:2605.15229`) quantifies `assume()` misuse and narrow generator ranges directly.
